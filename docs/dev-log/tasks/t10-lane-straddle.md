# 지시서 t10: 차선 밟음 감지 + 시간 축 보정 (쓰기)

## 배경
민옥이 app.py 로 `runs_in/mixkit_pov_31974_720.mp4` (낮, 산길, 1인칭, 다른 차 없음)를 돌려봤다. 결과: runs_out/upload_7abf5c9b5bc9/ (105프레임, 주의 71, 안전 34, lane_measurable=false 19).
- 바이크가 차선에 완전히 붙으면 차선 추적이 실패해서 "안전"이 나온다. 민옥 판단: 이건 주의 이상이어야 한다.
- 원인 추정: t07 에서 넣은 "바이크 영역(ego 마스크 최상단 아래) lane 픽셀 제거"가, 바이크 아래로 들어가는 실제 차선까지 지운다. 그 뒤 측정 불가 → LDW 미판정 → 안전.
- `.orch/DECISIONS.md` 2026-10-08 항목을 읽어. 측정 불가를 주의로 올리는 방식은 금지 (오탐).

## 할 것
1. 차선 밟음 감지: ego 영역 픽셀을 지우기 전에, lane 마스크(class 3)가 화면 하단 바이크 중앙 부근(ego 무게중심 x 주변)으로 이어져 들어오는지 확인. 들어오면 LDW 를 "차선 위 주행"으로 판정 (레벨은 노트북 LDW 체계에 맞춰 네가 제안하고 근거를 보고). 바이크 핸들/계기판 경계가 다시 차선으로 잡히는 오탐이 생기지 않게 조건을 둬.
2. 시간 축 보정 (시험적): 직전 유효 차선 상태를 짧게(예: 0.5~1초) 이어받는다. 편향이 커지다가 차선이 사라지면 직전 판정을 유지하거나 올린다. 이 보정만으로 새 경고를 L1 초과로 만들지는 마. 켜고 끌 수 있게 플래그로.
3. 편향 치우침 점검: 이 영상에서 "좌측 편향 16~19%"가 71프레임 내내 거의 일정하다. 실제 주행인지, ego_cx(ego 마스크 무게중심) 계산이 바이크 형태(휴대폰 거치대, 미러) 때문에 치우친 건지 확인해서 보고만. 고칠 필요가 있으면 판단 필요로 올려.
4. HUD 사유 문구에 "[zone boost]" 같은 영어 디버그 문구가 노출된다. 사용자용 reason 은 한국어로, 디버그 정보는 별도 키로 분리 (스키마에 키를 추가해야 하면 판단 필요로).
5. tools/frames_to_video.py 출력을 브라우저 재생 가능한 H.264 로 (imageio-ffmpeg 사용 가능). 지금은 FMP4 라 Gradio 에서 재생이 안 된다.

## 확인
mixkit 영상과 runs_in/night_ride_tmp.mp4 둘 다 engine.py 로 다시 돌려서, 수정 전후 비교: lane_measurable=false 수, LDW 활성 수, 등급 분포, 새로 생긴 "차선 위 주행" 프레임 번호 몇 개. debug_lanes.py 로 대표 프레임 이미지 저장.
