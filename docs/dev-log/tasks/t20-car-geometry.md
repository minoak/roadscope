# 지시서 t20: 자동차 모드 기하 재설계 (쓰기)

## 배경
자동차 블랙박스 실측 결과가 `.orch/research/car_dashcam_2026-10-09/` 에 있다. 먼저 `car_dashcam_geometry.md`(본문)와 `appendix_stage1.md`, `appendix_stage2.md`를 읽어라. 실측 스크립트는 같은 폴더 `scripts/stage1`, `scripts/stage2`에 있다. 다른 환경에서 쓴 참고 구현이다. 그대로 import하지 말고 필요한 부분만 engine.py 쪽으로 옮겨라.

요점은 이렇다. 수평선 높이가 영상마다 0.20~0.69H로 달라서 0.4H 고정 가정이 틀렸다. Depth Pro 원래 거리는 기하 거리의 약 0.23배로 무너졌다. 크기 변화 TTC는 충돌을 잡았다. 민옥이 결정한 내용은 `.orch/DECISIONS.md`의 2026-10-09 줄 세 개다.

## 할 것 (`--vehicle car`일 때만)
1. **영상 단위 보정 단계.** 판정 전에 영상(장면 전환이 있으면 구간) 앞부분에서 아래 값을 구해 고정한다.
   - 수평선 y와 소실점 x: 광류 확장 중심(회전 보정 필수, 정지, 회전 프레임 제외)을 기본으로 쓴다. 차선 소실점과 차량 박스 회귀(박스 바닥 y와 박스 폭으로 직선을 맞추면 절편이 수평선)로 교차 확인한다.
   - 보닛, 대시보드 띠: 차가 움직이는 동안 정지해 있는 영역으로 잡는다. 기존 `--hood-ratio`는 수동 지정용으로 남긴다.
   - 카메라 높이 H: 정면을 향한 차량 박스에서 H = W·(y_bottom − y_h)/w로 구한다(승용 W = 1.86 m, 버스, 트럭 2.5 m). 차선 두 줄이 잡히면 차선 비율로 보정한다. 둘 다 없으면 1.4 m.
   - 초점거리: 1280 폭 기준 600 px(폭에 비례). 점선 자는 이번에 넣지 않는다.
   - 보정값과 출처(어느 방법으로 구했는지, 신뢰도)를 결과에 남긴다. 보정에 실패하면 실패라고 기록하고 기본값을 쓴다.
2. **거리.** 바닥 위치 거리(f·H/(y_bottom − y_h))와 차폭 거리(f·W/w)를 둘 다 계산한다. 차폭 1.6~2.5 m 범위를 벗어나는 조합은 버린다. 경보에는 가까운 쪽을 쓴다. 화면 가장자리에 잘린 박스는 차폭 거리를 쓰지 않는다. Depth Pro 원값은 거리 계산에 쓰지 않는다. 박스 없이 가까운 물체를 잡는 보험으로만 남긴다. Depth Pro를 매 프레임 돌릴 필요가 없으면 줄여도 된다.
3. **차로.** 옆 거리 X = H·(x_bottom_center − x_vp)/(y_bottom − y_h)로 구한다. |X| ≤ 2.5 m를 내 차로로 본다. 픽셀 차선 기반 차로 침범과 corridor 판정은 자동차 모드에서 이 기준으로 바꾼다. 측면(BSW) 판정도 X 기준으로 맞춘다. 기준값은 DECISIONS에 있는 대로다.
4. **TTC.** 추적 중인 정면 객체(|X|가 차폭 이내)에 대해 박스 폭 증가율 TTC와 바닥 위치 변화율 TTC를 계산한다(0.5초 창 직선 맞춤). 두 방법이 모두 3초 미만이면 위험(L2) 이상으로 올린다. 치명(L3) 기준은 네가 정하고 근거를 보고해. TTC가 0.5초 창을 안정적으로 쓰려면 처리 fps가 더 필요할 수 있다. 자동차 모드의 기본 fps는 네가 정하고 실행 시간을 보고해.
5. **스키마.** 새 값(보정값, X, TTC)은 `.orch/contracts/frame_schema.md`에 추가한다. 기존 필드는 지우거나 의미를 바꾸지 않는다. viz.py가 읽는 필드가 깨지면 안 된다.
