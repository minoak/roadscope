# 지시서 t23: 자동차 모드 기하 코드 리뷰 (읽기)

## 배경
Claude가 t20에서 자동차 모드를 기하 기반으로 다시 짰다(`geom_car.py` 새 파일, engine.py의 `--vehicle car` 경로). 근거는 `.orch/research/car_dashcam_2026-10-09/car_dashcam_geometry.md`와 부록 두 개, 결정은 `.orch/DECISIONS.md`의 2026-10-09 줄들이다. t20 보고는 `.orch/runs/`의 `*-claude-t20-car-geometry/report.md`에 있다. 지금 Claude가 t22로 TTC를 판정에서 빼고 LDW 시간 보정을 없애는 중이라 engine.py가 바뀔 수 있다. geom_car.py의 기하 계산을 중심으로 봐라.

## 볼 것
1. **식이 맞는가.** 수평선, 소실점(회전 보정 FOE, 차선, 차량 박스 회귀), 카메라 높이 H = W·(y_bottom − y_h)/w, 바닥 거리 f·H/(y_bottom − y_h), 차폭 거리 f·W/w, 옆 거리 X = H·(x − x_vp)/(y_bottom − y_h). 부호, 단위, 해상도 비례(초점거리 600 px는 1280 폭 기준)를 확인한다.
2. **실패할 때 안전한가.** 보정 실패, 박스 바닥이 수평선 위나 아주 가까울 때(0 나누기, 음수), 잘린 박스, 보닛 추정 실패, 장면 전환. 실패하면 위험을 낮추는 쪽(미탐)으로 기우는 곳이 있는지 특히 본다. 원칙상 위험, 치명은 미탐을 줄이는 쪽이 우선이다.
3. **결정과 맞는가.** 차폭 1.6~2.5 m 게이트, 경보는 가까운 쪽 거리, |X| ≤ 2.5 m 차로, Depth Pro 원값을 거리로 쓰지 않음, 오토바이 모드 무변경.
4. **t20 보고와 실제 코드가 맞는가.** 보고에 적힌 판단(보닛 띠 45% 덮는 박스 제외, 카메라 높이 1.3배 불일치 처리, 근접 보험 5 m 등)이 코드에 그대로 있는지.

필요하면 `runs_out/nexar_t20/`의 결과(calib.md, frames.jsonl, meta.json)로 숫자를 확인해도 된다. engine 실행과 GPU 사용은 하지 마라.
