# 지시서 t27: 차 실내 영역 마스크 + 보정 안전장치 + 침범 기준, 30개 재실행 (쓰기)

## 배경
t26(보정 안전장치와 침범 기준)을 시작한 직후 민옥이 요청을 하나 더 해서 관리자가 t26을 3분 만에 멈췄다. t26에서 코드를 일부 고쳤을 수 있으니 engine.py, geom_car.py의 현재 상태를 먼저 확인하고 이어서 해라. t26 지시서는 `.orch/tasks/t26-calib-guard-intrusion.md`, 결정은 `.orch/DECISIONS.md` 마지막 세 줄이다.

## 할 것 1: 차 실내 영역 (자동차 모드)
민옥이 앱으로 neg_01711을 돌렸더니 화면 왼쪽 끝의 어두운 실내 영역(박스 대략 x 0~80, y 280~560)이 person으로 잡혔다. 바닥은 가림, 폭은 잘림으로 처리돼 보닛 경계 근접 상한 2.5 m가 붙었고, 정면 치명이 403프레임 중 371프레임 떴다. 결과는 `runs_out/job_85c1bf34551e4cb4adbd9189f5b63769/`. pos_00413도 화면 하단에서 시작하는 넓은 박스가 계속 치명이었다(t25 평가).

- 영상 단위 보정에서 지금의 보닛 "띠"(가로 한 줄)를 실내 **마스크**로 넓힌다. 대시보드, 보닛, A필러, 룸미러, 앞유리 반사, 화면에 박힌 워터마크, 시각 표시까지 포함한다. 방법은 네가 고르되, 차가 움직이는 동안 계속 정지해 있는 픽셀 같은 근거를 써라.
- 주의: 일정한 거리로 따라가는 앞차도 화면에서는 거의 정지해 보인다. 앞차를 실내로 지우면 미탐이 된다. 이 둘을 어떻게 구분했는지(예: 화면 테두리와 이어져 있는지, 보정 구간 내내 정지했는지, 질감 변화) 보고해라.
- 박스의 상당 부분이 실내 마스크 안에 있으면 판정에서 뺀다. 기준(겹침 비율)은 네가 정하고 근거를 적는다. 빠진 박스는 objects에 표시만 남긴다(예: `interior: true`).
- 실내 마스크 추정이 실패하면 박스를 지우지 않는 쪽으로 처리한다(t24 원칙).
- 확인: neg_01711의 이 박스가 빠지는지, pos_00413은 어떻게 되는지, 앞차를 따라가는 구간이 있는 영상에서 앞차가 지워지지 않는지. 대표 프레임에 마스크를 겹친 이미지를 영상 몇 개에 대해 `runs_out/nexar_t27/interior_check/`에 남겨라. 관리자가 직접 본다.
