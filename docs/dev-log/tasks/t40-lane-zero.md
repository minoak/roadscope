# 지시서 t40: 보정 단계에 차선 영점 추가 + 개발 세트 30개 재실행 (쓰기, GPU 사용)

## 배경
민옥 관찰: 자동차 블랙박스는 대시보드, 보닛이 화면 아래를 넓게 가려서 근거리 차선이 안 보인다. 그런데 LDW 판정 기준 행이 0.95H로 오토바이 값 그대로다(geom_car `LANE_BASE_ROW`, engine `y_check`). 보닛 띠는 중앙값 0.23H, 최대 0.47H라 0.95H는 대부분 가려진 곳이다. 그래서 보이지 않는 곳까지 차선을 연장해서 판정하고, 거의 모든 영상에서 차선 경고가 뜬다. t32, t34의 평소 위치 b도 같은 행에서 쟀다. 민옥 결정: 소실점처럼 영상 초반 보정 단계에서 차선 영점도 같이 잡는다. LDW 기준값 자체는 민옥이 나중에 직접 테스트하며 정한다. 이번에는 측정 위치와 영점을 바로잡는 데까지만 한다.

## 할 것 (자동차 모드만, 오토바이는 그대로)
1. **기준 행 y_ref:** 보정 구간에서 영상(장면 전환 구간)마다 정한다. 보닛, 내 차 영역 바로 위에서 YOLOPv2 차선 픽셀이 실제로 보이는 가장 아래 행이다. 두 차선이 보정 구간 프레임의 일정 비율 이상에서 보이는 행 중 가장 아래를 고르고, 비율과 여유 픽셀은 네가 정해 근거를 적는다. 0.95H 고정값은 자동차 모드에서 쓰지 않는다.
2. **차선 영점:** y_ref에서 내 차로 폭(px, 중앙값), 차로 중심과 소실점 열의 차이로 평소 위치 b를 구한다(t32 식을 y_ref에서). ±0.5 m 상한은 그대로 둔다.
3. **검산:** y_ref 행의 차로 폭을 미터로 바꾼다(px × H / (y_ref − y_h)). 2.75~3.75 m를 벗어나면 차선 영점 신뢰도를 낮추고 이유를 기록한다. 카메라 높이 H 쪽 문제일 수도 있으니 둘 중 무엇이 의심되는지도 적는다.
4. **LDW 판정:**
   - 매 프레임 y_ref에서만 잰다. 그 행에서 차선 픽셀이 실제로 안 보이면 연장하지 말고 "측정 불가"로 둔다.
   - 내 차 폭은 1.86 m로 잡고, y_ref에서 px로 바꾼다(1.86 × (y_ref − y_h) / H).
   - 차선 위 주행 판정의 거리 기준은 지금 값을 그대로 쓴다. 새 기준은 민옥이 정한다.
5. **영점 실패:** 차선을 못 잡은 구간은 LDW 전체를 측정 불가로 둔다. 다른 경고에는 영향을 주지 않는다.
6. **기록과 스키마:** meta car_calib에 y_ref, 차로 폭(px, m), b, 근거 프레임 수, 신뢰도, 실패 이유를 남기고 frame_schema.md에 적는다.

## 확인과 실행
- 먼저 CPU로 짧게(`CUDA_VISIBLE_DEVICES=-1`, 앞 15초) 두세 개 영상에서 동작을 확인한다.
- 그다음 GPU로 개발 세트 30개 전부를 `runs_out/nexar_t40/`에 돌린다. run_log.md에 영상별 y_ref(H 비율), 보닛 행, 차로 폭(m), b, 신뢰도를 남긴다.
- t34 대비 LDW 프레임(좌/우, 정상, 사고 영상)과 "측정 불가" 프레임 비율을 표로 낸다. LDW 말고 다른 경고가 바뀌었으면 이유를 적는다.
- 영상 몇 개(낮 고속도로, 밤, 보닛 큰 영상, 차선 영점 실패 영상)에 y_ref 선, 차로 폭, 내 차 폭 표시를 그린 확인 이미지를 `runs_out/nexar_t40/check/`에 남긴다. 민옥이 직접 본다.
