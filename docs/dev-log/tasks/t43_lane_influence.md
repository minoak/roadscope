# t43: 차선 검출이 소실점, 수평선, 카메라 높이, 거리에 주는 영향 (read)

## 배경
민옥 판단: LDW는 확신 없으면 꺼져도 된다(실제 LDWS처럼). 걱정은 하나다: 차선을 잘못 잡았을 때 그게 수평선/소실점, 카메라 높이 H, 거리(FCW) 계산을 틀어지게 하는가. 이게 괜찮으면 차선 쪽은 느슨하게 간다.

## 확인할 것 (자동차 모드, dev 30개 runs_in/nexar 결과만)
1. 코드 경로: engine.py, geom_car.py, car_models.py에서 차선 검출(YOLOPv2 차선, lane_zero)이 다음 값에 들어가는 모든 경로를 찾아 적어라: 수평선 y, 소실점 x, 카메라 높이 H, 바닥 기준 거리, 폭 기준 거리, 최종 distance_m, FCW 레벨. 각 경로가 "투표 하나"인지 "단독 결정"인지, 가중치, 이상치 제거가 있는지.
2. 데이터 (runs_out/nexar_t40의 meta.json, frames.jsonl, 필요하면 저장된 중간값):
   - 클립별로 수평선 후보(FOE, 차선 교점, 차량 박스 회귀)와 최종 수평선. 차선 교점 후보가 나머지와 얼마나 다른지(px).
   - 차선 교점 후보를 뺐다고 가정하면 최종 수평선이 몇 px 움직이는지(코드 로직을 재현해 계산할 수 있으면). 그때 FCW 거리, 레벨이 바뀌는 프레임 수.
   - 차로폭이 이상한 9클립(pos_00411, 00936, 00004, 00071, 00142, 00602, 00864, 00872, neg_01584)과 정상 클립을 나눠서 위 값을 비교.
   - H가 기본값인 3클립(pos_00411, pos_00071, pos_00602): 바닥 기준 거리와 폭 기준 거리의 비율 분포, 최종값이 어느 쪽에서 나왔는지 비율, FCW 레벨에 영향이 있었는지.
3. 결론을 세 줄 이내: 차선 오검출이 거리, FCW를 틀어지게 할 수 있는가(예/아니오/조건부), 근거 숫자.
