# t41: LDW 두 방식 비교 (자동차 모드, dev 30개)

## 목적
t40 차선 영점 뒤 LDW 주의(L1)가 늘고(정상 21→56) 영점 실패가 11/30이었다. 민옥이 직접 테스트 후 LDW 방식을 정할 수 있도록, 두 가지 대안을 dev 30개(runs_in/nexar)에 돌려 비교 자료만 만든다. 결정은 민옥이 한다. 기본 동작은 바꾸지 않는다.

## 비교할 방식
- V0 (기준): t40 그대로. runs_out/nexar_t40 결과를 재사용하고 다시 돌리지 않는다.
- VA (실패 기준 완화): lane_zero의 실패 판정을 완화해서 영점 성공 클립을 늘린다. 무엇을 얼마나 완화했는지 수치로 적는다. 차로폭 범위 밖이어도 성공으로 둘지 여부도 명시.
- VB (낮은 신뢰면 LDW 끔): 영점 차로폭이 2.75~3.75 m 밖이거나 영점 신뢰가 낮으면 그 구간 LDW를 "측정 불가"로 둔다(경고를 내지 않음). 신뢰 판정 규칙을 수치로 적는다.
- VAB (선택): 둘을 합친 것. 시간이 되면.

## 구현 규칙
- 방식은 설정값(환경변수나 CLI 옵션, 또는 engine 설정 키)으로 고를 수 있게 하고 기본값은 t40 동작(V0)과 동일해야 한다.
- 가능하면 t40 출력(JSONL, meta)에서 LDW만 다시 판정하는 오프라인 재판정으로 한다(tools/rejudge_lane_baseline.py 참고). 저장된 정보로 불가능하면 엔진을 다시 돌려도 된다(GPU 사용 허용, CUDA_VISIBLE_DEVICES는 건드리지 말 것, HF_HUB_OFFLINE=1, TRANSFORMERS_OFFLINE=1).
- LDW 외 경고(FCW, 측방 등)는 V0와 완전히 같아야 한다. 다르면 버그로 보고.
- 오토바이 모드는 영향이 없어야 한다. mixkit 105프레임으로 확인.

## 금지
- runs_in/testset(99개) 사용 금지. 읽지도 말 것.
- 판정 원칙 변경 금지: 단일 장면 판정, TTC 기록만, LDW 시간 평활 없음, 유령 박스 유지, FCW 3/5/10 m.
- 환경 설치/변경 금지. 커밋 금지. archive 폴더 수정 금지.
- web/ 폴더 수정 금지(Codex 담당).

## 산출물 (runs_out/ldw_variants_t41/)
- compare.md: 방식별 표: 영점 성공/실패 수, 차로폭 범위 밖 수, 정상 영상 LDW L1 수, 사고 영상 LDW L1/L2 수, 측정 불가 비율(정상/사고), 사고 이벤트 3초 전 LDW 포착 수. 클립별 표(30행). neg_01211, neg_02117 별도 언급.
- check/: 방식 간 차이가 가장 큰 클립 4~6개 확인 이미지(기준 행 y_ref, 검출 차선, 판정 표시).
- 각 방식의 장단점을 민옥 원칙(위험, 치명은 놓치지 않게, 주의는 과하게 뜨지 않게) 기준으로 3줄 이내. 추천은 해도 되지만 결정처럼 쓰지 말 것.
